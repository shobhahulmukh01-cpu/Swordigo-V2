# Alpha.3 — consequence, continuity and earned chapter proof

## Scope decision

Continue the supplied Canvas campaign and its four-room First Unwritten Day chapter. Retain Lyra/Aster, all three worlds and painted plates, original runes/guardians/endings, existing movement and Echo Gauntlet. No replacement engine, downloaded art, official Swordigo branding, mandatory post-ending errands or extra ending. Improvements are bounded; “100x” is an aspiration, not a measured result.

Three independent councils reviewed the restored delivered source; parent approved consequence/affordance/room identity, saved-anchor continuity, earned scene-aware proof, V4 update coverage and bounded rollback diagnostics. Preserve existing optionality rather than turning proof requirements into player progression gates.

## Implementation choices

- One pure selector derives NPC responses, Archive readings, mechanism explanations and optional journal advice from this journey. Distinguish carried Charter, published Charter and read signed testimony. Mercy and rekindle retain different truthful followthrough. Browser awards never substitute for journey progress.
- Delivery acknowledgements and return props require the committed delivery fact. Failed persistence changes neither facts nor rewards nor claimed consequences.
- Completed imports/resumes show the original ending first. Explicit continuation restores a validated saved chapter anchor; first continuation starts in Moonroot. Never resume an active cached fight from a portable save.
- Confirmed post-ending road checkpoint bug: automatic beacon lighting could replace canonical Hollowspire checkpoint and refill resources while visiting Moonroot. Disable automatic campaign checkpoint writes after completion; explicit rest restores vitals without rewriting canonical completion/checkpoint.
- Reuse existing rendering vocabulary for functional valves/vents/desks/testimony/console, cellar enclosure and room landmarks. Engine is a nonhuman device, retaining existing combat body and telegraphs. Delivery props introduce no persistent state or collision.
- Extend existing QA navigation/defense through a JSON-observation-only chapter controller, not gameplay shortcuts. Earn both original endings independently, then all rooms/deliveries/Charter/seals/opt-in Engine/finish, authored falls/death and validated earned save restore. Replay all actions and hash state. Synthetic client/storage/render fixtures remain explicitly separate.
- Retained native smoke exposed a fresh no-storage start regression: permit only a pristine story with a null storage handle to play with an explicit export warning. Keep live/saved replacement and delivery writes fail-closed. The old smoke validator was V3-only; use strict portable V4/base validation and preserve frozen legacy primary/backup checks. Superseded failure logs remain outside the final evidence folder.
- Keep digest/SRI/worker release coherence and old-client waiting policy. Add byte-exact V4 current/previous/revision preservation alongside frozen V3 and rush keys through failure, activation, offline, historical rollback and re-upgrade.

## Premortem and controls

| Failure | Control |
| --- | --- |
| Dialogue claims an unperformed repair | Pure fact matrix, signature/publication distinction, failed-write tests |
| Chapter continuation discards saved location | Certified-anchor validation, won-first/native explicit-continuation test |
| Map/door movement becomes free healing | Simulation-owned legal transitions, exact resource assertions, explicit-rest-only refill |
| Completed original stats change during errands | Canonical ending/checkpoint/stat assertions after every earned action |
| Test controller secretly completes quests | JSON observations, runner action whitelist, full input traces, exact replays |
| New props obscure hazards or reuse Veyr art | Collision unchanged, semantic silhouettes, desktop/portrait fixture review |
| Failed worker install mixes runtime generations | Content hashes/SRI, real historical worker and failed-install/offline tests |
| A green retry hides rollback flakiness | Preserve earlier timeout; predefined experiment, first-failure stop, bounded diagnostics |
| Tools distract from game integration | REA partial-static evidence retained; incompatible Lore deferred, Git kept |

## Evidence and release boundary

Current run results belong under `qa/correction/next-final/`; older chapter-final reports are historical. No test count is a human pacing, accessibility, device-performance, rights or production certification. A prior historical rollback timeout remains unresolved even if later bounded trials pass. Physical controllers, Safari/Firefox/iOS/Android/low-end devices, human first-play discovery/pacing, content rights and exact-commit remote CI/deployment remain independent holds. Keep public release manual and main-only.
