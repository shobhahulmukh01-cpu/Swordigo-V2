# Corrected sequel direction — build on supplied Emberwake

## Accepted correction
The previous Lumenblade replacement was the wrong implementation direction. Restore the supplied Emberwake as the canonical game. Preserve Lyra, Aster, Mara, Tovan, Orin, Veyr, original realms/heart story, painted art, simulation, controls, V3 saves, rune/cache/checkpoint/guardian IDs, both endings and gauntlet. Changes extend these systems; they do not substitute another game or revoke existing basic abilities.

## Actual parallel council
Three independent agents audited engine/compatibility, design/art/story, and risk/tools. All initially encountered a reset workspace; repository restoration unblocked evidence-based audits. Each then read the other reviews and wrote a second-round challenge/decision document. Reports distinguish static observation, prior recorded proof, proposals and untested claims. Parent verified all seven scripts against the newly supplied ZIP before changes.

## Resolution of disagreement
Design proposed additional rooms, abilities, a mandatory Charter return and an epilogue. Engineering identified concrete V3 completion and lifecycle incompatibilities; risk review challenged premature migration and over-scoping the correction. Decisions:
- **First corrective milestone:** canonical entry/package/cache; full-viewport preservation of supplied art; simulation-authorized travel; terminal death; explicit combined-input priorities; truthful save-success UI; fresh regression evidence. This is not the entire promised sequel.
- **Next substantive milestone:** distinctive optional routes and guardian patterns across the existing three realms; derived quest journal and changed NPC testimony from original validated discoveries. No new serialized quest/inventory or rewards yet; no forced replay of cleared fights.
- **Later sequel chapter:** nested side rooms, persistent delivery rewards, new optional heart abilities and epilogue only after explicit schema/migration, safe-scene transition, reward uniqueness and old-ending continuity gates. Do not silently add campaign entries or required sigils to V3.
- No mandatory Charter re-gating, arbitrary new GPU requirement, or replacement engine/scaffold. No claim of numerical “100x” effectiveness or measured commercial readiness.

## Tool findings
REA 6.4.0 was installed outside the repository with npm lifecycle scripts disabled and run as static analysis on the isolated supplied source extraction. The evidence report is local, attributed and not treated as a security sandbox or performance benchmark. REA is not a shipped game dependency. Existing source/tests remain authoritative for behavior.

Lore v0.10.1 CLI was downloaded and its SHA-256 matched the GitHub release digest. Execution fails because the prebuilt binary requires GLIBC_2.39, which this Amazon Linux host does not provide. No host-library replacement, server, repository migration or purported Lore-managed codebase. Git/GitHub remain authoritative.

Selected supplied references: Playwright for browser input/visual checks; existing Node tests and deterministic controller for regression/progression. Large agent frameworks are not installed solely to claim tool usage. No Touch Foo assets or commercial tool licenses are obtained through REA.

## Release gates
Baseline-to-upgrade save fixtures, recovered imports, denied writes, both original endings/gauntlet, ordinary-input campaigns/replays, full root/project-prefix browser tests, coherent offline update, source/art provenance and before/after visual review. Real-device FPS/thermal/input, Safari/Firefox, physical controllers, human pacing and independent accessibility/rights checks remain separate gates. No public rollout is called production-ready merely because CI passes.

## Implemented bounded milestone
The first corrective foundation and the three-realm substantive slice are implemented together. Route tests exercise continuous input-driven connections, encounter fixtures check timing/authority, and the campaign controller now runs against the encounter extension and optional routes. Journal states/NPC lines derive from existing flags; decorative restored-world details give backtracking feedback without adding reward/schema requirements. This is not the deferred persistent sequel chapter.

Final risk review identified cache-miss hash verification, failed-install cleanup, scope cache ownership, lifecycle import invalidation and storage-failure preservation. These are acceptance work, not optional polish. Final evidence is bound in `qa/correction/validation.json`; passing automation does not qualify untested hardware or legal rights.
